# Публикация Airport RMS бесплатно (ссылка для преподавателя)

Схема: **бэкенд на [Render](https://render.com)** (бесплатно) + **фронт на [Vercel](https://vercel.com)** (бесплатно). Преподаватель открывает **одну ссылку** на сайт Vercel; фронт обращается к API на Render.

---

## 0. Подготовка репозитория GitHub

1. Создайте репозиторий (можно приватный — Vercel и Render подключаются к GitHub).
2. В корень репозитория положите файлы, без которых не заработает импорт:
   - `практика 2026.xls` — для кнопки импорта Excel (путь в коде: корень репозитория).
   - при использовании XML: `backend/arrival_SPP_ru.xml`, `backend/departure_SPP_ru.xml` (или задайте пути через переменные окружения в Render, см. ниже).
3. Закоммитьте и запушьте `backend/`, `frontend/`, `backend/requirements.txt`, этот файл.

**Прогноз «Распределение» из папки «Выгрузки»** на Windows в коде задан абсолютным путём; на Render без доработки прогноз по файлам с диска может быть недоступен. Импорт Excel/XML и дашборд при этом работают.

---

## 1. Backend на Render (бесплатно)

1. Зайдите на [dashboard.render.com](https://dashboard.render.com) → **New +** → **Web Service**.
2. Подключите репозиторий GitHub → выберите нужный репо.
3. Настройки:
   - **Name**: например `airport-rms-api`
   - **Region**: ближе к вам / к преподавателю
   - **Root Directory**: `backend`
   - **Runtime**: `Python 3`
   - **Build Command**:
     ```bash
     pip install -r requirements.txt
     ```
   - **Start Command**:
     ```bash
     uvicorn app.main:app --host 0.0.0.0 --port $PORT
     ```
   - **Instance type**: Free

4. Переменные окружения (**Environment**), при необходимости:

   | Key | Value |
   |-----|--------|
   | `DATABASE_URL` | по умолчанию можно не задавать — будет SQLite в контейнере (данные могут сброситься при redeploy; для стабильности позже подключите бесплатный PostgreSQL, например Neon, и укажите `postgresql+psycopg://...`) |
   | `ARRIVAL_XML_PATH`, `DEPARTURE_XML_PATH` | см. пояснение ниже — **в типичном случае не задавать** |

   **Про XML (не путать с «Выгрузками»):** в Render эти переменные **не обязательны**. Нужны только два файла расписания в формате XML аэропорта (`arrival_SPP_ru.xml`, `departure_SPP_ru.xml`), которые вы уже используете для импорта. Положите их в репозиторий (удобнее всего в `backend/`, как в §0) — приложение найдёт их по умолчанию. Папку **«Выгрузки»** с прогнозом сюда класть **не нужно**; для облака она в коде и так не привязана. Переменные `ARRIVAL_XML_PATH` / `DEPARTURE_XML_PATH` задавайте только если файлы переименованы или лежат в подпапке, например `data/arrival.xml` (путь относительно каталога `backend/` или корня репо — см. `_resolve_path` в `backend/app/services/xml_parser.py`).

5. Нажмите **Create Web Service**. Дождитесь успешного деплоя.
6. Скопируйте публичный URL сервиса, например: `https://airport-rms-api.onrender.com`  
   Проверка в браузере: откройте `https://ВАШ-СЕРВИС.onrender.com/` — должен быть JSON с полем `app` и ссылкой на `/docs`.

**Важно (free):** сервис «засыпает» после простоя. Первый запрос после паузы может идти **30–60 секунд** — это норма для бесплатного Render.

## 2. Frontend на Vercel (бесплатно)

1. Зайдите на [vercel.com](https://vercel.com) → **Add New…** → **Project** → импорт того же GitHub-репозитория.
2. **Root Directory**: укажите `frontend` (важно: не корень монорепо).
3. **Framework Preset**: Next.js (определится сам).
4. **Build Command**: `npm run build` (по умолчанию).
5. **Environment Variables**:

   | Name | Value |
   |------|--------|
   | `NEXT_PUBLIC_API_URL` | `https://ВАШ-СЕРВИС.onrender.com` — **без** завершающего `/` (обязательно для реальных данных) |
   | `NEXT_PUBLIC_USE_MOCK` | `false` (рекомендуется зафиксировать явно, чтобы исключить demo-режим) |

   Для демонстрации интерфейса без бэкенда можно временно поставить `NEXT_PUBLIC_USE_MOCK=true`.

6. **Deploy**. После сборки Vercel выдаст ссылку вида `https://airport-rms-xxx.vercel.app` — **эту ссылку** отправьте преподавателю.

---

## 3. Проверка после деплоя

1. Откройте ссылку Vercel, подождите при «холодном» старте API.
2. В шапке нажмите **Обновить** или дождитесь загрузки данных; при пустой БД выполните **импорт** (Excel/XML) из интерфейса.
3. Если в консоли браузера (F12 → Network) запросы к API **красные** — проверьте:
   - точный URL в `NEXT_PUBLIC_API_URL`;
   - что бэкенд на Render уже «проснулся» (повторите запрос через минуту).

---

## 4. Ограничения бесплатного тарифа (кратко для преподавателя)

| Тема | Что сказать |
|------|-------------|
| Первая загрузка | Подождать до ~1 минуты, если давно никто не заходил |
| Данные SQLite на Render | После **нового деплоя** с GitHub база может быть пустой — снова импорт Excel/XML |
| Прогноз по папке «Выгрузки» | На облаке без доработки путей может не работать; остальной функционал — по импорту и нормативам |

---

## 5. Альтернатива одной ссылкой без двух сервисов

Можно поднять **только бэкенд на Render** и отдавать собранный статический фронт с того же домена через reverse proxy — это сложнее в настройке. Вариант **Vercel + Render** проще и остаётся бесплатным в рамках лимитов Hobby / Free.
